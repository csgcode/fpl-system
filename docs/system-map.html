The weekly cycle

The main session only coordinates: every step runs as its own agent, and it makes one git commit per gameweek. Rows are in run order. The retro waits for the collector's fresh snapshot, and the fixture analyst waits for the retro's corrections.

Core concepts

EP6
Expected points summed over the next six gameweeks. Every transfer, captain and bench choice is scored in it.
p_start
The chance a player starts in each gameweek. Analysts set it, and it is the main place judgement enters the model.
Blend and prior-only
Two readings of EP: this season's data blended with priors, and priors alone. A move must hold up on both.
Transfer gate
A free transfer needs +2.0 EP6 on the blend and no loss on prior-only. A −4 hit needs +6.0. Otherwise the transfer is banked, up to 5.
STATE block
The YAML at the end of final.md. It is parsed strictly and is the only thing that can drive a send to FPL.
Freshness gate
fpl flags re-checks injury and news for the squad and every buy just before the decision is written. Any change forces a REOPEN.
Predictions lock
The EP files frozen before the deadline, so the retro scores what was actually decided.
Corrections
Rules the retro writes for one agent (C1, C2…), active until a later retro retires them. Code fixes go to the backlog instead.
Backtest gate
A model change ships switched off. It is switched on only if re-scoring past rounds passes all five rules. None has passed so far.
Suggestions ledger
Each of your steers gets a status every cycle: followed, rejected, deferred, standing, expired or withdrawn.
Backlog
One triage list for findings outside any agent's remit. Agents only append to it during a cycle.

Guardrails

  • Squad rules are enforced in code: £100m budget, 2 GK, 5 DEF, 5 MID, 3 FWD, at most 3 per club, a legal starting XI.
  • Code does the arithmetic and the parsing, and agents supply judgement. No model's reading of prose ever drives a send to FPL.
  • Transfers go out only after you approve them in your own words, tied to the transfer id from the dry run. The lineup follows on its own.
  • Every prediction is written down before the deadline. Raw and decision files are never overwritten.
  • All FPL access goes through the fpl CLI, which caches every response and says how old it is. Login values are never printed.
  • Analysts judge players on underlying data (starts, minutes, xG, xA, defensive actions, news), not on transfers, ownership or price moves.
